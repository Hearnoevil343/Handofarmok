13. **HIGH — The World Map never draws the terrain.** Load Europe → THE WORLD MAP: the map area stays solid black (checked at 3 s and 11 s). The engine is running — a canvas exists (726×1189, visible), WebGL works (RTX 3080 via ANGLE), the brush cursor draws, and hovering updates the status bar with real Europe data (e.g. POS 063:059, WILDERNESS, EL 99, TE 37). Only the world itself is missing. Phaser boots twice on every visit (React StrictMode double-mount in dev, which is what `Launch (Windows).bat` runs).
    - **Reproduces every time:** 3 of 3 visits to The World Map (including coming back from the Export Vault with a world already edited) start black. The status bar also keeps showing the last hovered tile's old values until you hover again.
    - **Repro narrowed:** selecting another layer (Rainfall) does not draw it. **Painting one stroke does** — the whole map appears the moment the stroke finishes. So the only way to see your world is to edit it first; the default Sculpt tool is Raise at 100% strength, so that first stroke really changes the terrain.
    - **Likely cause (from reading, not tested):** `MainScene.create()` draws nothing itself; drawing happens on `PresetSwitched` / `stroke-finished`. `TileMap.tsx` emits `switchToPreset` + `RequestRedraw` in an effect that runs right after `createGame()`, before Phaser has booted and created the scene, so no listener exists yet.

15. **MED — Run Age panel contradicts itself about how long an age is.** The Drift hint says "Earth manages about 1.5 tiles per ten million years, which is roughly 4 here" (the scaled-planet reading the engine uses: 10 Myr per age, `timescale.ts`). The line directly under it says "At 129×129 this world is about 242 km across, so each age spans about 44 thousand years at Earth's average plate speed of 5 cm a year" — DF's literal map scale. Off by a factor of ~230, and the sim's climate eras and supercontinent cycle only make sense under the first.

16. **HIGH (design) — One press of Run Age erases a hand-made map.** On Europe, Age 1 already smears the coastlines into generic blobs; by Age 3 nothing recognisable is left. Engine reports 3% / 2% / 3% mountain against the panel's target of 14. There is no preview, no "this will reshape everything" warning in the button, and no way back except Ctrl+Z (untested for Run Age yet). For real-world presets and painted worlds this is the most destructive button in the app.

17. **MED — Run Age leaves the terrain blocky, with hard rectangles.** After three ages on Europe, at the same zoom as the original (map still a 570 px square), the land is made of flat patches several tiles across with straight edges, plus distinct rectangles (a grey-pink one bottom-right of the landmass). The original had tile-level detail. Looks like the "straight seam" artifacts `deStraighten` exists to remove, surviving it — and none of simlab's metrics measure blockiness.
18. **MED — Visible strip of raised ground down the left map edge after Run Age.** Bright grey column hugging x = 0 near the bottom. Matches simlab's `edgeBias` of 2.1–2.5 (edge columns much higher than the interior) — the worst-scoring metric in every run, now visible in the app.

19. **HIGH — Run Age, and every other World Tool, cannot be undone.** After three ages on Europe, Ctrl+Z three times changes nothing; the map stays at Age 3. Undo only restores snapshots from `WorldManager.saveSnapshot()`, which is called in exactly three places, all in `MainScene.ts`: fill, line start and brush stroke. Nothing in World Tools calls it, so Generate World, Run Age, Tectonic Age, Erosion, Rivers & Lakes, Derive Climate, World Events and World Forge are all one-way (confirmed by test for Run Age, by code for the rest). Combined with 16 (one press erases a real map) and 11 (nothing saved), there is no way back from a Run Age press except reloading the preset and losing everything else.
    - **Suspected follow-on (not tested):** if a brush stroke was painted *before* Run Age, its snapshot is still on the stack, so Ctrl+Z would jump back to before that stroke and silently discard every age run since.

20. **LOW — About page is out of date.** Calls the tool "Armok's Blueprint" (the upstream project) throughout; describes only painting, settings and export — no mention of World Tools, Run Age, Game View or Read This World. Describes the heightmap export as "a ZIP archive containing heightmaps for every preset" while the Export Vault card says "Extract the elevation strata as a bitmap".

21. **MED — About page's GitHub link is dead.** "Study the source scrolls (GitHub)" goes to `github.com/Pythongor/hand-of-armok`, which returns **404**. The upstream is `Pythongor/armoks-blueprint` (200) and this fork is `Hearnoevil343/Handofarmok` (200). `package.json`'s `repository`, `bugs` and `homepage` point at the same missing repo, so "report a fracture" has nowhere to go.
22. **LOW — Heightmap export still uses the old name:** `armoks_blueprint_export_<timestamp>.zip`.

23. **HIGH — Leaving the map page re-rolls the Run Age seed mid-history.** Ages 1–3 ran with seed 485051; after visiting the Export Vault and coming back, the panel showed 784031 and Age 4 ran with it, while the plates, plumes and sea level carried on from Age 3. Cause: `RunAge.tsx` keeps the seed in `useState(() => Math.random())`, so it is re-randomised whenever the panel remounts; the session (`getSession`) that holds the rest of the history is not. Consequences:
    - The history's randomness changes partway through for no visible reason.
    - It breaks the rule CHANGES §44 relies on (`seed − age` constant per history): the climate era sequence jumps to a different world's history. Age 3 "icehouse, glacial maximum" → Age 4 "greenhouse" is consistent with that, though an era change is also possible on its own.
    - Same pattern in code for **five** panels: `GenerateWorld.tsx`, `TectonicsTools.tsx`, `ErosionTools.tsx`, `DeriveClimate.tsx` and `RunAge.tsx` all use `useState(() => Math.floor(Math.random() * 1e6))`. A seed you typed or liked is lost whenever you leave the map.
27. **MED — Leaving The World Map wipes the undo history.** Found while verifying the undo fix: Run Age → Export Vault → back to the map → Ctrl+Z did nothing. `TileMap.tsx` calls `worldManager.switchToPreset()` on every mount, and `switchToPreset` calls `clearHistory()` even when the preset has not changed. So visiting any other page (settings, export, about) and coming back loses every undo step — brush strokes included. Not fixed yet.
28. **HIGH — Choosing a blueprint on World Settings measured the wrong world.** Second pass: with EUROPE and a generated EUROPE COPY loaded, Quick Setup and Read This World both reported 7,960 land tiles for each. `phaserMiddleware` only emitted `PresetSwitched`, and the only listeners are the map's Phaser scenes, so off the map `worldManager` stayed on whichever blueprint the map last showed — Read This World measured, and Apply Selected tuned, a different world from the one selected. Quick Setup also measured land once per mount.
29. **LOW — Status bar shows the tile as it was before a click.** It only updated on pointer move, so after a single click, fill or eyedropper it kept the old values until the mouse moved.
30. **MED — Read This World findings survived switching blueprint.** The list stayed on screen after selecting another blueprint, and Apply Selected wrote those proposals into the newly selected one.
26. **LOW — Plate boundaries barely show.** With "Show Plate Boundaries" ticked after Age 4 (4–6 plates), only a few short faint red fragments appear on the map rather than seams around each plate. Not measured; may be drawing only part of the plate map.

24. **HIGH — Layer locks are ignored by Run Age.** Locked Elevation (padlock highlighted), ran Age 4, exported again and compared with the export taken after Age 3: **16,573 of 16,641 elevation cells changed** (rainfall 15,989, temperature 16,580, drainage 16,314). The sidebar says "Locked layers are never written"; in code `lockedLayers` lives only in `paintSlice` and is checked by brushes, never by `useWorldWrite`. The feature exists to protect painted terrain, and the most destructive tool walks straight through it.
25. **LOW — Deleting the only blueprint silently does nothing.** `PresetsSidebar.handleDelete` returns early when one preset is loaded, with no message; the × button is still shown and clickable. (From code; not clicked.)
